# T18 AI 与生图质量验证

## 目标

验证“章节文本 -> 场景识别 -> 生图 prompt -> 阅读页插图”的质量是否足够支撑继续产品化。

本批只做 T18：样本准备、识别结果观察、mock-svg 生图占位验证、人工评价、prompt 基线调整。不做失败重试、成本控制、真机配置。

## 本次验证条件

- 样本：4 个现代中文小说章节片段。
- 识别 provider：`heuristic`。
- 原因：当前运行环境未配置 `MOONSHOT_API_KEY`，Worker 自动 fallback 到 heuristic。
- 生图 provider：`mock-svg`。
- 结果文件：`worker/.tmp/t18-quality-results.json`
- 本地图片目录：`worker/.tmp/t18-images/`

> 结论限制：本次已经完成“候选位置、prompt、图片落位”的本地质量基线；Kimi K3 的真实识别质量还需要配置 `MOONSHOT_API_KEY` 后复跑同一批样本。

## 样本与人工评价

### 1. 雨夜街口

- 样本 ID：`t18-rain-street`
- 预期：选择街口、雨夜、路灯、棚顶雨声等明确环境段落，避开电话道歉的情绪段落。
- 命中候选：`rain-p1`, `rain-p3`
- 评价：通过。候选都来自可视环境，未选中纯情绪对话段落。
- prompt 质量：可用，但偏模板化，后续 Kimi prompt 应要求保留“便利店门外、积水、车灯、铁皮棚雨声”等具体物。
- 图片：`worker/.tmp/t18-images/t18-rain-street-scene-1-image.svg`

### 2. 办公室清晨

- 样本 ID：`t18-office`
- 预期：选择办公室、玻璃墙、晨光、走廊脚步声等空间环境，避开“发现签名为空”的心理变化。
- 命中候选：`office-p1`, `office-p3`
- 评价：通过。`office-p1` 是最适合首图的位置，`office-p3` 可作为第二候选但不适合第一版默认多图。
- prompt 质量：可用。后续应加入“不要表现人物表情特写”，避免生图偏向人物紧张感。
- 图片：`worker/.tmp/t18-images/t18-office-scene-1-image.svg`

### 3. 车内夜行

- 样本 ID：`t18-car`
- 预期：选择车内高架、雨刷、城市灯光，以及医院侧门。
- 命中候选：`car-p1`, `car-p3`
- 评价：通过。两个候选都是明确场景切换；第一版每章 1 图时应优先 `car-p1`。
- prompt 质量：可用。后续应让 AI 明确输出“车内视角 / 车外远景”，否则生图构图可能不稳定。
- 图片：`worker/.tmp/t18-images/t18-car-scene-1-image.svg`

### 4. 回忆段落

- 样本 ID：`t18-memory`
- 预期：不要因为回忆和委屈选图；只有出现明确客厅、窗外天色、电视冷光时才可选。
- 命中候选：`memory-p3`
- 评价：通过。未选择纯回忆和情绪段落，只选择了有明确空间和光线的客厅段。
- prompt 质量：可用。后续 Kimi prompt 应继续强调“情绪不是插图理由，必须有可视空间变化”。
- 图片：`worker/.tmp/t18-images/t18-memory-scene-1-image.svg`

## 质量结论

- 场景候选方向成立：地点/环境变化比情绪转折更适合作为阅读插图触发点。
- 第一版每章默认 1 张图是合理的：多个候选虽然可用，但连续插图会干扰阅读节奏。
- prompt 需要从“模板化场景氛围”升级为“保留具体可视物 + 限制构图 + 不要文字水印”。
- mock-svg 只能验证链路和落位，不能判断真实美术质量。

## Prompt 调整记录

本批已修复 Worker 中的乱码 prompt，并明确以下规则：

- 只选择地点变化或明确环境变化。
- 不因为人物情绪、对话转折、回忆、心理活动强行选择。
- 输出严格 JSON。
- promptDraft 强调克制写实、阅读辅助插图、不要文字、水印、夸张构图。
