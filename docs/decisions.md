# 决策记录

## 2026-07-15：第一版必须是手机 App

决策：产品形态从一开始按手机 App 定义，不再以网页 HTML 原型作为目标形态。

理由：用户明确要求技术选型和产品方向必须面向 App。

## 2026-07-15：第一版采用设计稿确认后的可体验 App

决策：原型初步满意后，下一步进入可运行 App，而不是继续扩展静态界面稿。

理由：需要开始验证真实移动端流程和技术可行性。

## 2026-07-15：跨平台优先

决策：第一版同时考虑 iOS 和 Android。

理由：避免一开始绑定单端，技术选型以跨平台为主。

## 2026-07-15：采用 React Native

决策：移动端框架选择 React Native。

理由：适合快速实现 iOS + Android，可与 TypeScript / Node.js 后端保持同一语言栈，利于快速迭代。

## 2026-07-15：采用 Expo Dev Client

决策：React Native 项目形态选择 Expo Dev Client。

理由：比 Expo Managed 更有原生扩展空间，比 React Native CLI 更适合第一版快速启动。

## 2026-07-15：采用混合执行架构

决策：App 本地负责导入、阅读、缓存；云端负责 AI 场景识别、生图和图片存储。

理由：全部云端隐私和等待成本较重，全部本地第一版复杂度过高。

## 2026-07-15：后端采用 Node.js API + Python Worker

决策：Node.js / TypeScript 负责业务 API，Python Worker 负责文本解析和 AI 任务。

理由：业务接口和 App 同语言栈更顺；AI、文本处理和 EPUB 解析用 Python 更方便。

## 2026-07-15：数据与文件选择 Supabase

决策：第一版使用 Supabase Postgres 和 Supabase Storage。

理由：书籍、章节、任务、图片天然适合关系型数据；Supabase 能减少第一版基础设施搭建成本。

## 2026-07-15：网上书籍检索走云端统一处理

决策：后续网上书籍检索导入由云端处理，不让 App 直接抓取书源。

理由：便于控制版权、授权、格式标准化、缓存和后续书源扩展。

## 2026-07-22：第一版图片生成链路成立，下一步优先补任务基础设施

决策：T13 验证后，优先补齐“提交生成任务、任务状态、Worker 调度、App 轮询刷新”这层基础设施，再继续优化真实 AI prompt 或图片质量。

理由：当前已经跑通章节文本到场景图 URL 的闭环，但触发、进度、重试和状态刷新还没有产品化。没有稳定任务基础设施时，继续优化模型效果会难以在 App 内形成可演示体验。

## 2026-08-07：V6 首个在线书源使用 Project Gutenberg

决策：通过后端 Gutendex provider 搜索 Project Gutenberg，由后端下载并解析 EPUB/TXT，完整持久化后才导入书架。App 不直连或抓取书源文件。

理由：Gutendex 提供稳定的搜索和元数据接口，Project Gutenberg 提供可追溯的书籍页面与下载格式；云端统一处理便于去重、格式标准化、下载限制和版权状态留存。

## 2026-08-10：V6 第二个在线书源使用中文维基文库

决策：通过统一 `OnlineBookProvider` 边界并行搜索中文维基文库与 Project Gutenberg。中文维基文库只调用官方 `https://zh.wikisource.org/w/api.php`；单个书源失败时保留其它书源结果并返回 `sourceErrors`，全部书源失败时才中止搜索。

理由：中文维基文库提供可追溯的中文公开或授权作品及官方 MediaWiki API。书源差异收敛在服务端 provider 内，可以避免 App 直接抓取页面，并让后续合法书源沿用相同搜索、错误和导入协议。

## 2026-08-10：维基文库按根作品直接子页执行整本原子导入

决策：`sourceBookId` 使用作品根页面 pageid。导入只接受主命名空间、可识别且没有更深 `/` 层级的直接章节子页；完成章节发现、自然排序、正文提取和规模校验后，才通过单个 Supabase RPC 写入整本书。

理由：根 pageid 比标题稳定，直接子页规则可测试且可解释；先完整校验、后单事务持久化可以避免网络或解析失败留下半本书。非标准页面结构后续以独立规则扩展，不在本批猜测递归关系。

## 2026-08-10：维基文库正文使用 `zh-hans` 并保留来源归属

决策：正文通过 MediaWiki TextExtracts 的 `variant=zh-hans` 获取，保存为现有段落模型。导入书籍标记为 `authorized`，同时保存规范来源 URL 和 `source_attribution`；不统一宣称所有作品均为公版。

理由：官方语言变体能稳定提供简体正文；作品、翻译和版本的具体许可可能不同，因此必须保留来源页作为最终许可依据。远程 Supabase 必须先执行最新 schema，具备 `source_attribution` 列和新版 `import_online_book` RPC 后才能导入。
